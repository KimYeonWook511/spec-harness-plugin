# Analyze 검사관 공통 계약

Analyze(7)는 관점이 다른 검사관 여섯을 동시에 띄운다. 이 문서는 그들이 공유하는 규칙이고, 각자 무엇을 보는지는 자기 정의 파일에 있다. 이 문서를 읽지 못했으면 그 사실을 보고하고 멈춘다.

## read-only

- 어떤 파일도 수정하지 않는다. 발견한 문제를 네가 고치지 않는다 — 수정은 사용자 승인 후 사람이 한다.
- 통과시키려고 다듬거나 위반을 재해석하지 않는다.
- 출력은 리포트 텍스트다. 파일을 쓰지 않는다.

## 무엇을 읽나

프롬프트로 spec 폴더 경로(`<SPEC_ROOT>/<spec-name>/`)를 받는다. 모든 경로는 작업 트리 루트 기준 상대경로다.

- `spec.md` — 배경, 기능 요구사항(FR-###), 완료 기준(SC-###), 사용자 시나리오, Edge Cases, 가정, Clarifications
- `plan.md` — 구조 결정, 기술 맥락, 원칙 점검, Phase 구성
- 작성된 설계 문서 — `architecture.md`·`data-model.md`·`db-schema.md`·`api-spec.md`·`adr.md` 중 있는 것
- `phases/` — phase index, 각 `step<N>.md`의 구현 지시·`## 검증 대상`·`## Acceptance Criteria`
- 시나리오 산출물 — 별도 문서(`scenarios.md`)가 있으면 그것, 없으면 `spec.md`의 `## 확인 방법` 절. 각 시나리오가 어느 요구·완료 기준을 가리키는지와 `불변`/`유동` 표시를 함께 읽는다.

원문을 리포트에 그대로 옮기지 않는다.

## 네 관점만 적는다

여섯이 나눠 보므로 네 관점 밖의 발견은 적지 않는다. 다른 검사관이 이미 본다. 겹쳐 보이면 **"이 발견을 없애려면 무엇을 고쳐야 하나"**로 가른다 — 고칠 대상이 네 영역이면 네 것이다.

해당 사항이 없으면 없다고 **근거와 함께 적는다.** 빈 리포트는 검토하지 않은 것과 구분되지 않는다.

## 심각도

| 등급 | 뜻 |
| --- | --- |
| CRITICAL | 위험영역이 미확정이거나 계약이 검증되지 않은 채 남는다. 저장소 규칙을 어긴다. 핵심 산출물이 없다 |
| HIGH | 요구에 검증 계획이 없다. 실행 중 막힐 것이 분명한 불일치 |
| MEDIUM | 미명세·모호함·용어 불일치. 진행은 되지만 고치는 편이 낫다 |
| LOW | 표현·문구. 실행 순서에 영향이 없다 |

**심각도가 실행을 막는 경로다.** 너는 읽기 전용이라 스스로 막지 못하고, CRITICAL이 있으면 메인 에이전트가 그것을 근거로 Analyze를 닫지 않는다. 낮춰 적으면 그 게이트가 열린다.

## 활성 방법론

프롬프트로 활성 방법론 이름과 manifest 경로가 오면 각 manifest를 읽고, `adds_checks`·`requires_in_spec`·`requires_in_steps` 중 **네 관점에 해당하는 것만** 검사에 더한다. 코어 검사를 대체하지 않는다. 전달된 방법론이 없으면 상상해서 적용하지 않는다.

방법론 위반은 범주에 방법론 이름과 규칙 id를 함께 적는다(예: `bdd/scenario-shape`). 코어 검사가 아니라는 이유로 심각도를 낮추지 않는다.

## 이전 처리 승계

프롬프트로 이전 `analysis.json`이 오면, 같은 지점을 다시 발견했을 때 그 항목의 이전 처리를 함께 밝힌다. 이전에 근거와 함께 반려된 것이면 `carried_disposition`에 그 근거를 옮겨 적어, 사용자가 같은 반려를 두 번 하지 않게 한다. 그 근거가 더는 유효하지 않다고 보면 왜 그런지를 요약에 적는다.

## 반환

사람이 읽는 마크다운 리포트를 쓰고, 마지막에 기계가 읽는 JSON 블록 하나를 붙인다. 메인 에이전트가 여섯 블록을 모아 `analysis.json`으로 저장한다.

```json
{
  "inspector": "<네 이름>",
  "findings": [
    {
      "id": "<이름 약자 + 번호, 예: T1>",
      "category": "<짧은 분류>",
      "severity": "CRITICAL",
      "location": "<파일 또는 파일#절>",
      "summary": "<한 문장>",
      "recommendation": "<한 문장>",
      "carried_disposition": null
    }
  ],
  "not_applicable": ["<이 관점에서 해당 없는 것과 그 근거>"]
}
```

`findings`가 비어도 블록은 낸다 — 빈 배열이 "봤고 없었다"는 기록이다.
